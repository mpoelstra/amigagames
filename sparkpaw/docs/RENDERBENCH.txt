SPARKPAW AGA RENDER BENCHMARK
=============================

Experimental branch note (rb15)
-------------------------------

The `codex/sparkpaw-aga-4plus3-renderbench` branch changes only this isolated
benchmark from the accepted 3+3 layout to an AGA-native 4+3 dual playfield.
PF1 uses four odd-numbered bitplanes and pens 0-15; PF2 uses three even-numbered
bitplanes and AGA `PF2OF=16` so its pens live at 16-23. Bright magenta foreground
platforms prove that PF1 bitplane four is fetched. Rear geometry must retain its
independent quarter-speed scroll and separate blue palette.

This is not the game executable and does not contain the player, Strider, HUD or
gameplay. The first rb14 build overflowed its inherited 128-word Copper buffer
after adding the seventh pointer and AGA palette passes; Exec reported corrupt
memory during cleanup. Rb15 increases the allocation to 256 words, guards every
Copper emission and records actual usage/capacity/overflow in `renderbench.log`.
Test rb15 before any production renderer migration. The accepted
3+3 game remains recoverable as commit `26b281a` on `main`.

Run sparkpaw-renderbench from its directory. Click the left mouse button to
exit, or wait approximately one minute.

After a normal exit it writes renderbench.log beside the executable
(PROGDIR:). The log records the exact build, display/fetch values, frame
count, exit reason and Workbench restoration path. Please send this small
text file with any visual report.

This first isolated benchmark tests only the risky display foundation:

- a private PAL Copper display, independent from Intuition and Workbench;
- two independently hardware-scrolled 672x256 planar bitmaps;
- foreground at full speed and background at quarter speed;
- explicit 320x256 display/fetch timing and one update per PAL frame;
- no gameplay, sprites, HUD, full-screen copies or per-frame drawing.

Expected result: a full-height display with two differently scrolling layers.
The foreground automatically travels left/right. The background moves slower.

If it is malformed or half-height, photograph it and report whether it was
started from HD or ADF. If it is correct and smooth, the next benchmark adds
the tile-edge updater and an AGA hardware sprite.
